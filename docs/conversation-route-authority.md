# Conversation route authority

This bounded revision separates typed story ownership from ordinary learned
intent fallback. The archived social-routing candidate remains rejected.

The story adapter computes a read-only `StoryPlan`, then applies it once after
memory/calculation/fact routing. Supported story operations and explicit unsafe
assertions retain authority regardless of the learned label. A fully consumed
bounded social form may preserve story context; this existing grammar comes
from public CLINC TRAIN evidence and is not expanded in this revision.

An ordinary question or command ignored by the story adapter can still return
its existing learned proposal. Failure to match the finite social grammar is
not independently a reason to veto that proposal. This is routing retention,
not a claim that a learned label proves semantic correctness.

The appended-social guard continues to reject unsupported suffixes and explicit
punctuation-separated clauses. For supported coordinated movement, an actor
already present in the story can disambiguate a greeting-shaped name. For
example, after establishing an actor named Hello, `Hello and Mira went to the
cellar` retains the existing movement behavior. A newly introduced actor with
that name is inherently ambiguous; the independent probe records that case
without declaring baseline acceptance unsafe.

Preregistration and independent boundary contracts were frozen before runtime
edits. Existing original social, memory and regression evaluators are reused
unchanged from the read-only archive or repository. See
`tools/conversation/route-authority/HANDOFF.md` for measured acceptance, exact
binary identity, limitations and reproduction commands.
