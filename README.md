# glassmind

A system you talk to in plain English about Rust code it can see, that
answers in English, with **no neural network and no LLM inside it**.
Everything it knows is Rust source you can read: its types are the concepts
it can think about, its functions are how it reasons, and every answer can
show the trace that produced it (`--explain`).

LLM coding agents build it, but none runs inside it. They write its grammar,
words and concepts, and an improvement loop keeps a change only when an
automatic scorer says it helps. All of glassmind's data was generated by
Claude Opus 5.5 working backwards from tasks whose answers were computed by
tooling; **no human-written requests were tested**.

## Using it

```sh
cargo build --release
# ask about a repository (name=path, repeatable; defaults to the current directory)
./target/release/glassmind ask -s tds=../top_down_shooter_game "which functions call spawn_wave?"
# the full trace: words, parse, meaning, references, dropped readings, reply rules and their rounds
./target/release/glassmind ask --explain -s tds=../top_down_shooter_game "what calls spawn_wave"
# talk interactively; Tab offers what can come next, including real names
./target/release/glassmind chat -s tds=../top_down_shooter_game --session talk.json
# machine-readable outcome
./target/release/glassmind ask --json -s tds=../top_down_shooter_game "what calls spawn_wave"
# what may come next after an unfinished input
./target/release/glassmind complete -s tds=../top_down_shooter_game "which functions call spa"
```

Edits are proposed as a set of changes and applied only with `--apply`; it
never commits.

## How it is built

Three layers, kept apart by the crate graph (`cargo run -p glassmind-depcheck`, run in CI):

| crate | layer |
|---|---|
| `glassmind-meaning` | language-neutral, data-neutral meaning types, and the `Language` / `World` interfaces |
| `glassmind-grammar` | the grammar's fixed building blocks: an Earley parser that carries meaning values, reads left to right, keeps every reading, reports where it got stuck and what may come next; and the same rules run backwards to speak |
| `glassmind-english` | English: tokenizer (the only code that reads raw text), categories, phrase values, rules, function words, replies |
| `glassmind-world-rust` | the Rust world: items, kinds, relations, `syn` indexing, lookup, answering |
| `glassmind-english-rust` | English words for the Rust world's kinds and relations |
| `glassmind-mind` | dialogue: readings, name resolution, preference rules, sessions, traces |
| `glassmind-rules` | every rule's stable ID, the loop round that added it, and runtime switches |
| `glassmind` (cli) | `ask`, `chat`, `complete`, `eval`, `rules` |
| `glassmind-loop` | the scorer, the size counter and the improvement loop |
| `tools/oracle` | computes exact answers with `syn`, independently of glassmind |
| `tools/datagen` | plans conversations from tasks and phrases them with Claude Opus 5.5 |

The meaning layer depends on no language and no world; English depends on
no world; worlds depend on no language.

## Data and scoring

1. `tools/oracle` picks tasks in real repositories at fixed commits and
   computes their exact answers (`docs/tasks.md` is the contract).
2. `tools/datagen/plan.py` builds conversations backwards from tasks:
   single requests, follow-ups that say "it", corrections, context
   requests, "why" after an edit, user-defined nicknames.
3. `tools/datagen/phrase.py` phrases them in several styles (prompt
   families: terse, chatty, newcomer). A different prompt family writes
   the held-out set, about repositories never used in training.
4. `tools/datagen/finish.py` checks every turn with tooling and an LLM
   checker and writes `inputs.jsonl` and `labels.jsonl`.
5. `glassmind-loop score` compares outcomes with labels: right costs 0, a
   refusal 0.5 to 1 depending on how far it got, a confident wrong answer 10.

## The loop

`glassmind-loop run --state DIR` (or `tools/loop-service.sh start DIR` to
run it as a detached, resumable service) alternates:

- **growth rounds**: group the training failures, start up to four headless
  Claude Code agents, each in its own git worktree inside a bubblewrap
  sandbox that hides the held-out data, with one failure group, examples,
  and an earlier accepted change;
- **compression rounds**: switch every rule used by at most one right
  answer off by its ID, and brief an agent to delete what nothing needs and
  merge or generalize the rest.

A change is accepted only if it builds and passes clippy, the tests and the
layer check; lowers training cost plus 0.01 per syntax token of mind code;
turns no right or honestly refused training turn wrong; does not worsen the
held-out score; and is not vetoed by a reviewer agent for keyword spotting,
special-casing or knowledge in the wrong layer.
